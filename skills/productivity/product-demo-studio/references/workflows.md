# Tool choices for a batch

The seven local workflows are available tools, not seven required outputs. Select tools after the interview. A user usually wants several creative directions and then a polished winner; comparing renderer engines is a separate, explicit option.

dependencies.lock.json pins the source revisions used in the originating workflow. Fetch only the chosen sources, read their real entrypoints, and retain their licenses.

| ID | Workflow | Native integration |
|---|---|---|
| C01 | Guizang | Root SKILL.md and its initializer/checker; product components with React/GSAP/browser rendering. |
| C02 | HyperFrames | skills/product-launch-video/SKILL.md and CLI/core guidance; HTML timeline and native CLI export. |
| C03 | Remotion official | skills/remotion-best-practices/SKILL.md plus render/multimedia guidance; flexible React editing. |
| C04 | Video Shotcraft | Root SKILL.md and actual PageCam implementation; UI camera direction. |
| C05 | Testreel | README.md and docs/recording-definitions.md; actual browser-operation recording. |
| C06 | Product Launch Motion v2 | Root SKILL.md; pure seek(t), springs, subframe HTML capture and FFmpeg. |
| C07 | claude-motion community | .claude/skills/motion-design/SKILL.md and optional sound skill; local motion helpers/Mask/SFX. Distinct from hosted products. |

Demo IDs such as V01 identify creative variants. Workflow IDs C01–C07 identify tools. Record both without confusing them. One demo can use Testreel capture plus Remotion editing. Multiple demos may use the same engine.

Only when the user requests a tool benchmark: keep comparable story/specs/assets, invoke actual native pipelines, record versions/adaptations/failures, and distinguish shared edits from independent exports. A failed engine is not replaced by relabeling another renderer's output. One run and concurrent timings do not establish reliability or fair performance rankings.
