# Interview: no assumed demo specifications

Start with the product and purpose. Ask one focused question, wait for the answer, and continue with the next missing decision. Prefer 2–3 concrete choices plus free text when useful. Do not dump a questionnaire or re-ask known answers. Use the user's language.

## Decisions to collect

| Group | Details to resolve |
|---|---|
| Purpose | Product, intended audience, where they will encounter the video, desired takeaway/action. |
| Product proof | Specific journey/tasks, available source/URL/recording, real operations versus screenshots, safe test data, claims to include/exclude. |
| Creative direction | Existing brand/assets, references, tone, pacing, text density, CTA or explicit no-CTA choice. |
| Output specs | Languages, placement/aspect ratio/resolution, duration, audio/voice/captions, rights/budget and deadline. |
| Batch and review | Number of demos, which differences to explore, local/hosted review, who may view, and how the user wants to select/polish. |

Split a group into several short rounds. Ask concrete preference questions, not implementation questions the agent can resolve. Tool choice can remain the agent's responsibility unless the user has a preference.

## Unknowns stay unknown

Do not assume English/Chinese, 30/45 seconds, portrait/landscape, sound/no sound, a style/palette, seven demos, seven engines, hosting, or public/private access. Templates are not requirements. A previous product's settings are not a new customer's brief.

If asked for recommendations, explain a small set of options and record the accepted choice. If the user explicitly says “you decide,” record which decisions were delegated and state the selected assumptions before building. Otherwise keep unresolved fields empty and continue the interview.

## Confirm the batch brief

Summarize at most five groups:

1. Audience, goal, product journey and claims.
2. Source/footage/data boundary.
3. Brand/style/audio and accepted creative treatment.
4. Exact output specs and batch count/differences.
5. Review/delivery method, audience and unresolved blockers.

Ask for agreement/corrections. Production starts from this confirmed brief, not the initializer. Save answers and the next question so the interview can resume.

## Review is another conversation

After the batch, ask which demo ID to develop and which changes matter. Let the user point to moments, copy, pacing, framing or sound. Preserve the selected original, create a new revision, and show the result for the next round. “Make more options” creates a new batch round under the current brief; “polish V02” revises that demo only.
